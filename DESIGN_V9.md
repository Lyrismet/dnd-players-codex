# Incadent v9 - функциональное описание для разработки

Документ раскладывает v9 на задачи: что сделать, по каким правилам, какие данные и тесты нужны, как принять. Дизайн утверждён
и закрыт, этот документ - рабочая спецификация для реализации. Сделанное отмечается в `FEATURES.md` (там карта фич, здесь
способ и приёмка). Источник: issue #50 "Предложения для дизайна v9" и его обсуждение.

## Как пользоваться документом

- **Вид экранов** - интерактивный прототип `Players Codex v9.dc.html` в корне репозитория (состояния и тексты внутри файла,
  открывается в браузере). Для всего, что v9 не меняет, вид совпадает с `Players Codex v8.1.dc.html`. Иконки прототипа
  подключаются файлом `pc-icons.js`: его надо положить рядом с прототипом (см. 5.1), иначе иконки не отрисуются.
- **Прототип упрощён.** В нём нет `origin_id`, затухания краёв, `launchMode`, настоящего сопоставления сессий, шита "Что в
  снаряжении", большого шрифта листа и тоста "Повысить уровень остальным", а часть логики (откат удаления, отсечение личных
  предметов, откат отдыха) проще, чем требуется. Там, где прототип и документ расходятся, **верен документ**, расхождения
  помечены в тексте ("в прототипе ...").
- **Строки берутся не из прототипа**, а из `values`/`values-en` по словарю `CLAUDE.md` (место, отряд, день, хиты,
  нажмите). Юридический текст SRD тоже из `strings.xml`. Тексты макета - иллюстрация.
- Задачи берутся по шагам дорожной карты (приложение А), не как попало. Миграции БД - приложение Б, тесты - В, раскладка
  по пакетам - Г, сквозная приёмка - Д.
- Дизайн закрыт. Если при реализации выясняется, что макет не отвечает на вопрос или противоречит документу, это вопрос
  владельцу, не повод придумывать. Пресеты других систем, список заклинаний и прочее - в разделе "Не брать в работу".

## Готовность задачи (для каждой задачи без исключений)

1. Код по слоям `CLAUDE.md`: Presenter, Ui, Screen, Circuit-фабрика, домен без фреймворков, `data` за интерфейсом.
2. Любое изменение схемы - `.sqm` с `DEFAULT` или backfill и тест миграции на старой версии (Б). Старые данные живут.
3. Все строки в `values` и `values-en`, плюрали через `<plurals>`, словарь проекта. Нового хардкода текста нет.
4. Новый визуальный блок сначала ищется в `CORE_COMPONENTS.md`; новый примитив добавляется туда же в том же PR. Новый
   общий пакет презентации добавляется в `SHARED_PRESENTATION` (`ArchitectureTest`).
5. Чистая логика под `core/*` и `feature/*/domain` с тестом в `commonTest`. Имена тестов в обратных кавычках без запятых и
   точек (Kotlin/Native).
6. Архив только для чтения: новые кнопки скрыты и отсекаются в презентере.
7. Проверка: `./gradlew build -x :shared:linkReleaseFrameworkIosArm64 -x :shared:linkReleaseFrameworkIosSimulatorArm64`,
   `./gradlew ktlintFormat`, `./gradlew detekt`. Устройство проверяет владелец, агенты эмулятор не запускают.
8. Пункты `FEATURES.md` отмечаются `[x]` после приёмки, не раньше.

## Сквозные правила

- Не перегружать записи полями: новое поле либо заменяет старое, либо уходит в "Подробнее". Экран "Я" под это правило не
  попадает, это лист персонажа.
- Кодекс не меняется молча: всё, что приложение вычислило само (из заметки, из отдыха, из файла), применяется только
  после нажатия игрока и с Undo.
- Архивная кампания только для чтения: новые кнопки и правки скрыты и отсекаются в презентерах (`CodexReadOnly`,
  `SessionDetailReadOnly`).
- Все строки в `values` и `values-en`, плюрали через `<plurals>`.
- **Схема БД меняется только с миграцией** (`.sqm` и тест на старой версии, см. `CLAUDE.md`). У тестеров живые данные,
  правило v8 "база пересоздаётся" больше не действует.
- Правила системы живут в одном заменяемом месте. Для v9 это шаблон D&D 5e по SRD 5.1 (формулы листа персонажа, 7.3),
  класс и тип восстановления ресурса приложение само не выводит, их вводит игрок. Любую числовую плитку можно заполнить
  просто числом. Пресеты других систем - в бэклоге.
- Термин "хиты" везде, не "HP". Пустое значение - серый прочерк "—".
- Крупные числа (хиты, бонусы, кошелёк, степперы) набираются шрифтом Inter, не засечным: ноль не должен походить на "О".
- Метка своего персонажа "я", обращения к игроку на "вы". Тексты без угадывания пола людей и персонажей.

## Эпик 1. Общие компоненты и мелкие правки

### 1.1 Закреплённая панель действия

- Компонент `core/designsystem`: кнопка на скруглённой подложке с небольшой тенью, прибита к низу экрана или шита. Один
  компонент и для шитов, и для обычных экранов.
- Учитывает клавиатуру (`imePadding`) и жестовую навигацию, не перекрывает таб-бар. Сначала проверить `FloatingBar` и
  `CORE_COMPONENTS.md`: если основа там есть, параметризовать, не писать новый.
- Первое применение - "Добавить в кодекс" в форме записи. Кандидаты на переезд: "Начать бой", строка "+ Создать запись"
  (2.1). Запись в `CORE_COMPONENTS.md` в том же PR.

### 1.2 Закреплённая шапка шита

- В `AppBottomSheet` шапка (`AppSheetHeader`: закрытие и заголовок) не уезжает при прокрутке содержимого. Тонкая линия под
  шапкой появляется, только когда содержимое прокручено.
- Одна правка в компоненте, не правки по экранам. Приёмка: в самом длинном шите (форма NPC) после прокрутки вниз кнопка
  закрытия на месте.

### 1.3 Затухание у краёв списков

- Модификатор в `core/designsystem`: край затухает только там, где есть ещё прокручиваемое содержимое
  (`canScrollForward` / `canScrollBackward`). Нечего прокручивать - затухания нет.
- Применить к спискам кодекса, сессий, шитам выбора. Проверить вместе с 1.1: поверх закреплённой панели не должно быть
  двойной тени.

### 1.4 Строка "+ Создать «X»" в шитах выбора

- `AppSelectSheet` получает необязательное действие "создать". Строка появляется при непустом запросе без точного
  совпадения и ведёт в быстрое создание записи (как "+ Новый NPC"). Пустой шит остаётся чистым.
- Одна правка закрывает все шиты выбора: места, квесты, виды, типы существ.

### 1.5 Файл из Telegram открывается как часть Telegram

- Причина (проверено по манифесту): `MainActivity` объявлена как `singleTop`, при `ACTION_VIEW` из другого приложения окно
  попадает в его задачу. Перейти на `launchMode="singleTask"`.
- Проверить на устройстве (проверяет владелец): холодный старт из Telegram, повторное открытие файла при уже открытом
  приложении (`onNewIntent`), кнопка "Назад" и экран недавних приложений.

### 1.6 Атрибуция SRD

- В "О приложении" ссылки сейчас обычный текст: сделать их нажимаемыми (открываются в браузере) и текст выделяемым и
  копируемым. Тот же блок в форме вида.
- Заголовок "Названия существ" (`settings_about_srd_title`) заменить на "Материалы SRD 5.1": с v9 из SRD берутся ещё шаблоны
  ресурсов (7.4). Текст атрибуции брать из `settings_about_srd_value` и дополнить, не теряя формулировок лицензии CC BY 4.0
  ("переведены и адаптированы", "Wizards of the Coast не поддерживает это приложение"). Короткий текст в макете это
  иллюстрация. Ссылки: `dnd.wizards.com/resources/systems-reference-document` и
  `creativecommons.org/licenses/by/4.0/legalcode`. Строки в `values` и `values-en`.

### 1.7 Подсказки "?"

- Общий компонент `core/designsystem` (запись в `CORE_COMPONENTS.md`): значок "?" рядом с заголовком раздела, по
  нажатию шит с коротким объяснением и кнопкой "Понятно". В шите может быть легенда (например, три состояния кружка
  владения). Область нажатия значка не меньше 48 dp.
- Только по нажатию, сами не всплывают. Тексты в `values` и `values-en`, не хардкодом.
- Девять мест: владение навыком, КД ("вписывается рукой", с упоминанием строки "Откуда"), пассивное восприятие, ячейки
  заклинаний, ресурсы, кошелёк, временные хиты, спасброски от смерти, режим экспорта "для друга" (что не передаётся).
  Утверждённые тексты в прототипе, ключи `HELP`.

## Эпик 2. Упоминания и заметки записей

### 2.1 Строка "+ Создать запись" в дропдауне `@`

- Внизу списка всегда закреплённая строка. Записей 3 и меньше - с подписью "Нет нужного? Напишите имя, и мы создадим
  запись". Записей больше - компактное "+ Создать запись". Когда после `@` уже набрано имя - "+ Создать «X»" (v8 1.1).
- Нажатие открывает то же создание, что в v8 1.1 (имя и тип), чип встаёт в текст, Undo.
- Причина: человек создал запись в кодексе и, нажав `@` в сессии, видит один пункт и не знает, что запись можно создать
  прямо отсюда. Строка использует компонент 1.1 и логику 1.4.
- Приёмка: в новой кампании с одной записью `@` показывает подписанную строку создания.

### 2.2 `@` в поле заметок записи

- Поле "Заметки" в форме записи и в быстром режиме (удержанием) получает тот же дропдаун и те же токены
  `@[Имя|n:12]`. В отображении - нажимаемые чипы, нажатие открывает шит упомянутой записи.
- Сама запись в своих заметках не предлагается. Виды вставляются без количества. Удалённая запись - "?"-тег, как в
  сессиях.
- Приёмка: в заметках NPC написано `@Мирдейл`, в карточке виден чип, нажатие открывает место.
- Макет: прототип v9 (набор `@Мир`, закреплённая строка, подпись при трёх и меньше, чип в карточке). Компоненты те же, что
  в заметках сессии.

### 2.3 Связи из заметок

- После сохранения заметки записи приложение предлагает связать упомянутое с полем записи:

| В заметках записи упомянут | Предложение |
|---|---|
| место (у NPC) | добавить в "Где встретить" |
| NPC (у места) | добавить в "Кто здесь" |
| NPC (у квеста) | поставить "от кого", если поле пусто |

- Предложение - один шит или тост после сохранения, не во время набора: "Связать: ☑ Мирдейл → Где встретить",
  применяется нажатием с Undo. Уже существующая связь не предлагается. Для мест действует запрет циклов (v8 3.3).
- Отказ запоминается для пары "запись + упоминание" (в БД, с миграцией) и больше не повторяется. В архиве предложений нет.
- Макет: прототип v9. Предложение стоит под заметками, одно на поле ("Мирдейл - указать в «Где встретить»?" с кнопками
  "Связать" и "Не надо"). "Связать" заполняет поле, текст заметки не меняется, тост "Связано · … Отменить".
- Логика выбора предложений - чистая функция в домене с тестом в `commonTest`.

## Эпик 3. Кодекс: отряд, виды

### 3.1 Повышение уровня остальным

- Игрок повышает **свой** уровень (форма или быстрая правка): после сохранения тост "Повысить уровень остальным (N)?" с
  действием. Нажатие повышает уровень тем, у кого он равен старому уровню игрока, и показывает Undo. Молча ничего не
  меняется.
- Не затрагиваются павшие, персонажи без уровня, и тот, у кого уже 20 (`PartyStatRanges`). Некого повышать - тоста нет.
- Отдельной кнопки "Повысить всему отряду" нет: повышение редкое действие.
- Логика отбора - чистая функция с тестом.

### 3.2 Подсказка, если "я" не назначен

- В "Отряде" есть персонажи, но ни у одного нет метки "я": плашка вверху "Выберите своего персонажа" с кнопкой выбора из
  списка. Выбор ставит метку одному, Undo. Закрывается крестиком, возвращается после следующего импорта.
- Тот же выбор используется на экране "Я" без персонажа (7.2).

### 3.3 Свои типы существ

- Тип существа выбирается в `AppSelectSheet`, а не чипами. 14 типов 5e встроенные, игрок добавляет свои через "+ Создать"
  (1.4). Свои типы переименовываются и удаляются там же, в шите, по кнопке правки строки.
- Хранение: встроенные - по ключу из SRD-списка, свои - строки в БД (с `campaign_id`). Миграция сохраняет текущие значения.
- Удаление своего типа: виды остаются, значение типа у них пустое и показывается "—". В шите есть строка "Без типа" для
  сброса. Перед удалением диалог с перечнем затронутых видов. Каскадного удаления нет.
- Свои и встроенные типы пишутся одним регистром (строчными). Макет: прототип v9 (шит типа).
- Приёмка: создать тип "Механизм", назначить виду, удалить тип - вид на месте, тип "—".

## Эпик 4. Импорт, экспорт и слияние

Контекст: игроки обмениваются файлами перекрёстно. Лиза записала сессию и скинула файл, на следующий день Артём
записал свою, оба импортировали друг друга. Одну и ту же сущность оба часто создают независимо (например, "Кахури").

### 4.1 Метка "я" и обезличенный отряд

- Метка "я" (свой персонаж) путешествует только в экспорте "для себя" (4.7). В экспорте "для друга" метка снимается, и
  все персонажи отряда уходят обезличенными.
- Обезличенный отряд: имя, класс, раса, уровень, имя игрока, портрет, отметка павшего ("†"). Не уходят: хиты, КД, заметки об
  отряде (если не включён отдельный тумблер), лист персонажа, личные вещи, метка "я". Хиты и КД нужно было бы постоянно
  обновлять, а заметки об игроке могут быть личными.
- При импорте поля, которых нет в файле, не затираются: Лире без хитов в файле её хиты остаются.
- При слиянии метка локальной записи не меняется. Если "моя" запись совпала с чужой, выжившей остаётся она (с метки "я"
  начинается выбор выжившего).
- Тест: слить кампании, в которых моя запись совпала с чужой, метка не слетела и запись не задвоилась; импорт файла без
  хитов не обнуляет локальные хиты.

### 4.2 Стабильные идентификаторы (`origin_id`)

- `origin_id` (UUID) у кампании и у каждой записи кодекса, сессии, заметки, боя. Создаётся один раз, не меняется,
  переезжает в файл. Новые таблицы (предметы, ресурсы) создаются с ним сразу.
- Миграция с заполнением существующих строк, например `lower(hex(randomblob(16)))`, плюс тест "данные выжили".
- Таблица алиасов: после объединения двух записей выжившая помнит оба `origin_id`, иначе следующий файл от одного из
  игроков снова придёт как новая запись.
- Формат файла: версия схемы растёт, файлы без `origin_id` (v8) сопоставляются по имени и типу, как раньше.
- Заодно это фундамент под будущую Firebase-синхронизацию (см. "Заметки на будущее").

### 4.3 Классификация при импорте

- Каждая запись файла: **новая**, **такая же** (совпал `origin_id` или алиас, отличий нет), **изменена** (совпал
  `origin_id`, отличия есть), **совпала по имени**.
- Точное совпадение имени и типа (после нормализации через `NameKey`) - кандидат на объединение, галочка стоит по умолчанию.
- Нечёткое совпадение (одно имя содержит другое: "Кахури" и "Деревня Кахури") - подсказка без галочки: "Похоже на
  существующее: Кахури. Это одно и то же?" с кнопками "То же" (объединить, выжившая - с меткой "я", иначе локальная, оба id в
  алиасах), "Разные" (запомнить пару, не спрашивать) и "Решу позже" (запись из файла в этот раз не берётся, файл можно
  импортировать снова).
- Сессии сопоставляются по дню и названию (номеров в базе нет): "Огни на холме · 24 окт есть у обоих. У вас 6, в файле 4,
  одинаковых 2" с выбором "Объединить заметки" (по умолчанию, "станет 8 заметок по времени") и "Оставить отдельно" (рядом
  встанет вторая сессия этого дня с пометкой "из файла"). Макет: 18c.
- Повторный импорт того же файла показывает "Ничего нового: всё из файла уже есть в кампании" с кнопкой "Закрыть" и ничего не
  меняет. Тест на идемпотентность.

### 4.4 Экран сравнения

- Сводка: "5 новых записей · 3 изменённых · 1 сессия", блок "Нужно решить · 3". Над конфликтами две кнопки "Взять всё из
  файла" / "Оставить моё": они ставят выбор всем конфликтам сразу, по каждой записи его можно поменять. Внизу "Решено 3 из
  3 · Отменить можно в настройках" и кнопка "Объединить". "Взять всё" заменяет и текст заметок на файловый, откат есть
  ("Отменить последний импорт", экраны отката в прототипе).
- У изменённой записи поля "у вас / в файле" с выбором по каждому. У текстовых заметок третий вариант - "Оставить оба
  текста", только вручную в самой записи.
- Проверка на устройстве владельцем, на реальных двух файлах.

### 4.5 Слияние заметок сессии

- Заметки с неизвестным `origin_id` добавляются в сессию, существующие не трогаются. Порядок по времени создания. Токены
  упоминаний переназначаются на выжившие записи (как в v8 5.3).

### 4.6 Удаления

- Удаления между игроками не передаются: чужие данные мы не удаляем, свои удаления другим не отправляем.
- Чтобы удалённое не воскресало при каждом импорте, удалённые `origin_id` помнятся локально (таблица, с миграцией, в файл
  не попадает). В сравнении они лежат свёрнутой строкой "Вы удаляли раньше: 2" с кнопкой "Вернуть". Undo удаления
  убирает запись из этого списка (в прототипе откат метку не снимает, делать по документу).

### 4.7 Экспорт "для себя" и "для друга"

- Вверху экрана экспорта переключатель **"Для себя | Для друга"**. Режим пишется в файл и в имя файла ("Тени Блэквуда ·
  личная копия", "Тени Блэквуда · для друга").
- **Для себя**: полная копия без галочек. Записи, сессии, бои, лист персонажа, личные вещи и кошелёк, метка "я", хиты, КД и
  заметки отряда. Единственный выбор - тумблер "С фото" с оценкой размера.
- **Для друга**: "Вся кампания / Выбрать" и "С фото", как в v8 5.2. Над кнопкой плашка: "Отряд уйдёт без хитов, КД и заметок,
  без вашего листа и личных вещей. Друг не увидит ваших пометок о нём", с подсказкой "?" и списком того, что не
  передаётся. Отдельный тумблер "Заметки об отряде" (выключен) для случая, когда игрок сам хочет отдать описания героев.
- Личные предметы (владелец "я" или другой персонаж отряда) уходят только в режиме "для себя". Мировые предметы (владелец
  NPC, место, "общее") это обычные записи кодекса, они идут на общих основаниях и в режиме "для друга". В прототипе
  вырезаются только предметы владельца "я", вырезать нужно и предметы других персонажей отряда.
- Импорт читает режим из файла. Файл "для себя": предлагается восстановить кампанию целиком, с листом и меткой "я", при
  уже существующей метке вопрос "заменить?". Если такой файл открыл другой игрок, показывается "Это личная копия другого
  игрока". Записи и сессии берутся как обычно, а лист, личные вещи и метка идут одним тумблером "Взять [имя] как моего
  персонажа" (выключен): лист без метки никто бы не увидел. Хиты, КД и заметки отряда отдельным тумблером, тоже выключен.
  При своей копии и уже существующей метке выбор "Оставить с устройства" (по умолчанию) или "Взять из файла" относится
  только к листу, вещам, кошельку и метке, хиты и заметки идут по общему правилу слияния. Формулировки без угадывания пола
  ("Персонаж в файле", "Лист Лиры"). Файл "для друга": обычное слияние (4.3-4.6).
- Зависимости (v8 5.2) берутся сами и показаны пунктиром.

### 4.8 Экспорт сессии текстом

- Пункт "Поделиться текстом" в меню сессии, системный share. Заголовок, вступление, заметки по порядку. Чипы упоминаний
  становятся обычными именами без знаков.
- Переключатели в окне перед отправкой: **"С вступлением"** (включён) и **"Действующие лица"** (выключен по умолчанию).
  Действующие лица - блок в конце, по строке на каждый вид записей: "NPC: Старый мельник", "Места: Мирдейл", "Виды: Гоблин
  ×3", "Отряд: Лира, Торвин" (без описаний, пустые строки не выводятся).
- Вступление - шуточная фраза из набора в `strings.xml` (`values` и `values-en`), случайная, но не та же, что в прошлый
  раз. Правила фраз, потому что приложение не знает рода персонажа и имена вроде "Арианна'тэль" не склоняются: имя только в
  именительном падеже, глаголы только в настоящем времени или существительные, без прошедшего времени. Имя - из метки
  "я". Нет метки - общие фразы без имени.
- Примеры: "{имя} раскрывает свиток: вот что было на самом деле.", "{имя} уверяет, что всё было именно так.", "Трактирная
  байка. Автор - {имя}. Совпадения с реальностью случайны.", "Летопись, записанная при свете свечи. Автор - {имя}.",
  "{имя} диктует хронику, чернила ещё не высохли."
- Формирование текста - чистая функция с тестом в `commonTest`; парность наборов в `values` и `values-en` проверяется.

## Эпик 6. Предметы

### 6.1 Модель

- Новая сущность "предмет": название, количество (по умолчанию 1, степпер, от 1 до 9999 без разрядов: "×1250"; на единице минус
  удаляет предмет с Undo, состояния "закончилось" нет), необязательная **цена за штуку** (число до 9 999 999 с пробелами
  в разрядах и монета, по умолчанию золото), владелец, заметки, фото,
  `campaign_id`, `origin_id`. Таблица с миграцией.
- Один шит "Предмет" для добавления и правки: название, количество, цена, заметки с `@`, "Удалить предмет" при правке.
  Нажатие на строку списка открывает его. В строке вторая строка "50 золотых за штуку", если цена задана.
- Основной сценарий - **свой инвентарь**. Владелец по умолчанию "я". Остальные значения (персонаж отряда, NPC, место,
  "общее") остаются необязательным полем. Если метки "я" нет - владелец пуст, "общее".
- "Передать" между владельцами не делаем.

### 6.2 Список в "Отряде"

- Вкладка "Отряд" получает переключатель "● Персонажи / ○ Предметы" (`AppSegmentedTabs`, как "Именные / Виды" у NPC;
  знаки заменит 5.1). Отдельной вкладки у предметов нет.
- Строка: иконка или фото, название, "×3", мелко владелец. Пустая вкладка: "Предметов пока нет", "+ Добавить предмет".

### 6.3 Упоминание

- Токен с буквой `i`, нейтральный цвет, статуса нет. Предметы не участвуют в авто-упоминаниях (названия - обычные слова).
- В дропдауне вторая строка: владелец и количество. Упоминание ссылка, оно количество не меняет.

### 6.4 Карточка и "Снаряжение"

- Карточка предмета: фото, название, количество со степпером, владелец, связанные заметки.
- В карточке владельца (персонаж, NPC, место) раздел "Снаряжение", правится удержанием с мультивыбором, как "Кто здесь":
  шит "Что в снаряжении" с блоками "Выбрано" и "Остальные", у чужих предметов подпись "у Лиры · перейдёт", внизу
  "Готово · N". Подпись у места "в Мирдейле" собирается из названия, склонение проверять на других названиях. В прототипе
  этого экрана нет (там только смена владельца с тостом "Снаряжение изменено"), делать по описанию выше.
- Архив только для чтения.

## Эпик 7. Вкладка "Я", ресурсы, отдых

### 7.1 Таб-бар с центральной кнопкой

- Решено: пять мест в баре - Сессии, Кодекс, **Я** (центр, круглая, поднята над баром), Бой, Настройки. Настройки остаются
  отдельной вкладкой, под шестерёнку не уходят.
- Утверждено: нахлёст 7 dp, круг 48 dp. Закреплённые кнопки над баром ("Начать бой", панель 1.1) стоят выше бугра и его не
  перекрывают. У нижнего края списков отступ под бугор.
- Область нажатия круга не меньше 48 dp, индикатор жестов на iOS не перекрывается. Бейдж раунда у "Бой" остаётся.
- В `BottomTabBar` - параметр "центральный элемент", не отдельный бар.

### 7.2 Экран "Я": лист персонажа

- Свой персонаж - та же запись отряда с меткой "я", не копия. Задумка: игрок не уходит в другие приложения и заметки за
  числами, поэтому экран это **лист персонажа**, а не дубль боя. Правило "не перегружать записи полями" касается кодекса,
  этого экрана оно не касается.
- Закреплённая шапка: портрет, имя, класс и уровень, раса. Хиты (текущие, максимум, временные). Плитки: КД, инициатива,
  скорость, бонус мастерства, пассивное восприятие.
- Вкладки: **Лист / Ресурсы / Вещи**, у заклинателя ещё **Заклинания** (7.5, правило показа там же). Последняя открытая
  запоминается.
- Шапка при прокрутке вкладки "Лист" сворачивается при любом размере шрифта: имя и плитки уходят, закреплены хиты, вкладки
  и ряд значков характеристик (7.3). Иначе на малом экране для списка не остаётся места.
- Хиты правятся нажатием на значение: открывается `NumberPadSheet` с переключателем − / + и отдельное "Временные".
  Красной кнопки "Урон" на экране нет, чтобы не путать с боевой. Бой читает те же хиты, источник один.
- Реакции на экране нет. Состояние реакции остаётся только в бою (v8 6.4).
- Нет метки "я": пустое состояние "Выберите своего персонажа" со списком отряда и "+ Новый персонаж" (выбор из 3.2).
- Пока открыт экран, в баре подсвечен только круг "Я". На остальных экранах круг не золотой, подсвечена своя вкладка.

### 7.3 Вкладка "Лист"

- Шаблон 5e по SRD 5.1. Шесть характеристик плитками: крупно **бонус**, мелко значение. **Игрок вводит значение**, бонус
  считается: значение минус 10, пополам, вниз. Правка бонуса идёт через значение, поэтому +4 всегда понятно, это 18 или
  19.
- Спасброски: у каждой характеристики отметка владения, бонус = бонус характеристики плюс бонус мастерства.
- Навыки: 18 навыков SRD с фиксированной привязкой к характеристике. Отметка нет / владею / компетентность (бонус
  мастерства ×2). Скрытое поле "поправка" (±) для предметов и черт. Блока "Избранные" нет: найти нужный навык должно быть
  быстро и по любому названию.
- Вид как на бумажном листе игрока: **одна колонка, шесть полос** по порядку Сила, Ловкость, Телосложение, Интеллект,
  Мудрость, Харизма. Над полосами закреплённый ряд значков "СИЛ −1 · ЛОВ +2 · ТЕЛ +1 · ИНТ +4 · МУД +1 · ХАР +0": видны все
  шесть бонусов, нажатие прокручивает к полосе, подсвечен значок полосы вверху экрана, лупа поиска в конце ряда, при поиске
  ряда нет, при крупном шрифте два ряда по три. Заголовок "Характеристики и навыки ?" прокручивается вместе со
  списком. В каждой полосе слева плитка характеристики (название, бонус крупно, значение мелко), справа список
  строк одного вида: "Спасбросок" первой, затем навыки этой характеристики (кружок владения, название, бонус). Без
  переносов. У Телосложения только "Спасбросок". При крупном системном шрифте плитка становится шапкой полосы над списком (название слева, бонус крупно справа, значение мелко рядом), строки занимают всю ширину, высота растёт вместе со шрифтом, переносов во вторых названиях нет; шапка листа при прокрутке сворачивается, закреплены хиты, вкладки и ряд значков в два ряда по три. Отдельного блока навыков и значка
  спасброска в плитке нет.
- Названия навыков в русских изданиях различаются. Основные названия по листу игрока: Аркана, Анализ, Уход за животными,
  Внимательность, Выступление. Вторая подпись мелким серым у навыков с распространёнными синонимами: Аркана (Магия),
  Анализ (Исследование, Расследование), Уход за животными (Дрессировка, Обращение с животными), Внимательность
  (Бдительность, Восприятие), Выступление (Исполнение), Ловкость рук (Проворство). В заголовке блока значок лупы с поиском по
  названию и синонимам. Список синонимов сверить с изданиями. Алфавитного списка нет.
- Бонус мастерства берётся из уровня: +2 на уровнях 1-4, +3 на 5-8, +4 на 9-12, +5 на 13-16, +6 на 17-20. Повышение
  уровня меняет все зависящие числа само, это главная цель.
- Считаются также инициатива (бонус Ловкости) и пассивное восприятие (10 плюс бонус Восприятия). КД и скорость вводятся
  руками. В правке КД есть необязательная строка "Откуда · для себя" (например "кольчуга 16 + щит 2"), только для игрока,
  никуда не считается. Поле хранится в таблице листа (миграция, `.sq` и `.sqm`), строки в `values` и `values-en`.
- Характеристика заклинаний выбирается здесь, она открывает вкладку "Заклинания" (7.5). Не выбрана - вкладки нет.
- "Вдохновение" (SRD 5.1): флажок есть/нет без чисел, используется редко, поэтому места в шапке не занимает. Переключатель
  "○ Вдохновение" стоит справа в строке заголовка "Характеристики и навыки" и прокручивается вместе с ней, включённое
  золотое. Долгий отдых его не трогает, мастер выдаёт его сам.
- Языки и владения текстом, особенности текстом, оба поля с `@` (2.2).
- Блок "О персонаже" ниже "Особенностей": подкласс, предыстория, мировоззрение (короткий свободный текст) и "Личность"
  (черты характера, идеалы, привязанности, слабости, один текст с `@`). Те же поля в правке персонажа и в шаге 1 первого
  заполнения. Списков выбора нет, в SRD по одному подклассу и одной предыстории.
- Любую плитку можно заполнить просто числом без формулы, если система не 5e. Все формулы 5e собраны в одном месте
  (`feature/codex/domain`, например `FifthEditionRules`), чтобы позже заменить их пресетом (см. "Не брать в работу").
  Чистая логика с тестами в `commonTest`: значения 1, 8, 9, 10, 11, 20, 30, уровни 1, 4, 5, 20.
- Данные: таблица листа персонажа (запись отряда, шесть значений, отметки владения, поправки, характеристика заклинаний,
  КД, "откуда" у КД, вдохновение, скорость, `origin_id`) с миграцией. Поле `fav` ("избранные") из прототипа не переносить. Значения вне 1-30 отсекаются, как `PartyStatRanges`.

### 7.4 Вкладка "Ресурсы"

- Только у своего персонажа. Общий механизм счётчиков: название, максимум (вводит игрок), текущее, группа.
  Ячейки заклинаний - частный случай (группа по уровням). Типа восстановления у ресурса нет: всё возвращает долгий отдых
  (7.6), а то, что восстанавливается на коротком отдыхе, игрок возвращает нажатием на пипс.
- Ресурсы строками с пипсами. Ячейки заклинаний показываются на вкладке "Заклинания" (7.5), здесь их нет.
- Тратятся нажатием на пипс, правятся удержанием, и в "Я", и в бою. Состояние одно, оба места читают один источник.
- "+ Из шаблона": заготовки названия из SRD 5.1, максимум вводит игрок. Шаблоны не подставляются сами по классу. Перечень
  собрать по SRD 5.1 (способности классов с ограниченным числом использований, ячейки заклинаний), каждое название
  сверить с SRD. Атрибуция - 1.6.
- Максимум после повышения уровня игрок правит сам, текущее не пересчитывается.
- Таблица с миграцией, чистая логика долгого отдыха с тестами в `commonTest`.

### 7.5 Вкладка "Заклинания"

- Показывается, только если выбрана характеристика заклинаний (7.3) или есть ячейки. У варвара, воина без магии и другого
  не-заклинателя её нет. Появляется сама: игрок добавляет шаблон "Ячейки заклинаний" в "Ресурсах" или выбирает
  характеристику на "Листе", убирается удалением ячеек и снятием характеристики. Пункта меню "Показать/скрыть вкладку" нет
  (он есть в прототипе, где вкладка по умолчанию у всех, делать по этому правилу).
- Ячейки рисуются как на бумажном листе: столбцы по уровням 1-9, пипсы стопкой в каждом, виден весь запас за один взгляд.
  Показываются только уровни с максимумом больше нуля (у заклинателя высших кругов в столбцах 6-9 по одному пипсу).
  Нажатие на пипс тратит или возвращает, удержание - правка. Это те же ресурсы группы "уровни", состояние общее с боем.
- СЛ (8 плюс бонус мастерства плюс бонус характеристики) и бонус атаки заклинаний (бонус мастерства плюс бонус
  характеристики) по выбранной характеристике.
- Под ячейками зарезервировано место под список заклинаний по кругам (известные и подготовленные), реализация позже, в v9
  его нет. В прототипе место показано пустой областью, чтобы список лёг сюда без перекройки вкладки.

### 7.6 Отдых

- Одна кнопка "Долгий отдых". Короткого отдыха в приложении нет: подлечиться можно кнопкой лечения, а ресурсы и ячейки,
  которых обычно две-три штуки, игрок возвращает нажатием на пипс.
- Долгий отдых возвращает **всё**: все хиты (временные уходят), все ячейки и все ресурсы. Выбора и исключений нет.
- Перед применением короткая сводка в одну строку без перечня по ресурсам ("хиты 22 → 28, все ячейки и 2 ресурса
  восстановятся"), при полных хитах "хиты полные". Переключателя "Восстановить хиты" нет.
- Переключатель "Записать в сессию" (выключен, только если есть идущая сессия): системная заметка "Долгий отдых" в текущей
  сессии.
- Спасброски от смерти сбрасываются вместе с хитами.
- Применение с Undo, который откатывает только изменения отдыха, а не весь снимок состояния (в прототипе откатывается всё).
  Значок костёр. Кнопка "Отдых" стоит в шапке листа рядом с хитами и видна на всех вкладках.

### 7.7 Вкладка "Вещи"

- Предметы с владельцем "я": название, количество со степпером (у всех одинаково), вторая строка с ценой, если она
  задана, "+ Предмет". Нажатие на строку открывает шит "Предмет" (6.1). Это вид кодекса "мои предметы", отдельного хранения
  у листа нет.
- **Кошелёк**: одна карточка, золото крупно ("34 золотых"), остальные монеты (серебряные, медные, платиновые,
  электрумовые) строкой под ним только если не равны нулю. Названия словами, без сокращений "зм, см, мм". Полей добавлять и
  убирать не нужно, в хранилище пять чисел до 9 999 999, на экране длинные числа с пробелами.
- "Изменить" открывает калькулятор, как для хитов (`NumberPadSheet`): переключатель − / +, выбор монеты (золото по
  умолчанию, остальные под "Ещё"), подсказка курса ("1 золотая = 10 серебряных"). Строка "Всего ≈ 36 → 21 золотых" показывает итог до и
  после операции, если есть мелкие монеты. Длинное число в карточке кошелька не переносится ("1 234 567" в одну строку,
  неразрывные пробелы). Курс 5e: 1 платиновая = 10 золотых, 1 золотая = 10 серебряных, 1 электрумовая = 5 серебряных, 1 серебряная
  = 10 медных, он лежит в шаблоне 5e (7.3). Обмен монет - в бэклог.
- Заметки персонажа: текст с `@` (2.2).

## Эпик 8. Версия приложения и задел под проверку обновлений

### 8.1 Вывод версии

- Версия (например "9.0.0") выводится на сплэше мелким текстом внизу и в "Настройки → О приложении" отдельной строкой
  "Версия". Номера сборки в скобках нет (вынесено в 8.3). Лоадер и название на сплэше не меняются, на сплэше в прототипе
  также "Incadent / TTRPG JOURNAL / Совместимо с 5e · SRD 5.1".
- Единый источник: интерфейс `AppVersion` (`core/appinfo`) с `expect`/`actual`: на Android из `versionName` и `versionCode`
  (`PackageInfo`), на iOS из `CFBundleShortVersionString` и `CFBundleVersion`. Строку в `commonMain` не хардкодить.
- Сейчас номера расходятся: Android `0.8.1` (`androidApp/build.gradle.kts`), iOS `MARKETING_VERSION=1.0`
  (`iosApp/Configuration/Config.xcconfig`). До выпуска привести к одной схеме.
- Строки в `values` и `values-en`, тест на форматирование.

### 8.2 Задел под сверку версий

- В `core/appinfo`: тип версии (major, minor, patch) с разбором строки "0.8.1" и сравнением, результат сверки
  `UpdateStatus` (`UpToDate`, `Available`, `Unknown`), чистое правило `UpdatePolicy`, решающее, достаточна ли разница между
  актуальной и установленной версией, чтобы предложить обновление. Порог разницы в одном месте. Тесты в `commonTest`.
- Интерфейс `LatestVersionSource` (актуальная версия или `null`) без реальной реализации: сетевого слоя и бэкенда пока нет.
  В графе Metro заглушка, возвращающая `null`, статус `Unknown` и ничего не показывается. Настоящий источник живёт в
  `data/remote` позже.
- Презентер настроек получает `UpdateStatus`. Строка "Доступна новая версия" в "О приложении" показывается только при
  `Available`, по нажатию открывается страница приложения в магазине (`expect`/`actual`, позже).
- Это groundwork впрок (см. раздел про заготовки в `CLAUDE.md`): интерфейс и логика без реализации источника допустимы.
- Не входит в задачу: сетевые запросы, диалог обновления, принудительное обновление.

### 8.3 Решения владельца

- Откуда брать актуальную версию: решено, Firebase (ориентир - версия 0.9.5, вместе с синхронизацией). До тех пор работает
  заглушка `LatestVersionSource`, возвращающая `null`.
- Какая разница версий повод предложить обновление (любая более новая, минорная и выше, только мажорная).
- Только предложение или бывает и обязательное обновление.
- Единая схема нумерации для Android и iOS.
- Показывать ли номер сборки (`versionCode`, `CFBundleVersion`) рядом с версией ("9.0.0 (412)"): сейчас в макете нет.

## Заметки на будущее: Firebase

- Метка "я" сейчас локальная и хранится в записи. Когда появится вход через Google, персонаж "я" должен привязываться к
  аккаунту (запись участника кампании ↔ аккаунт), а не к метке в БД: синхронизируется персонаж игрока. Локальная метка
  при этом остаётся представлением на устройстве.
- `origin_id`, алиасы и локальные надгробия из эпика 4 - это те же стабильные id, `updatedAt` и мягкие удаления, о которых
  говорит `CLAUDE.md` в разделе про синхронизацию. Конфликты синхронизации решаются тем же экраном сравнения.
- Синхронизация будет только в платной подписке, поэтому она обратима: локальная база всегда полная и остаётся
  источником правды. Без подписки приложение работает как сейчас, а после отмены подписки данные остаются на устройстве
  целыми. Привязка к аккаунту и серверные id не должны быть единственным способом найти запись, поэтому локальные
  `origin_id` и ключи не заменяются серверными. Включение и выключение синхронизации не должно ничего удалять.
- Решения по Firebase (стратегия конфликтов, провайдеры, Firestore или Realtime Database) остаются открытыми.
