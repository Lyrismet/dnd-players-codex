# v9: брифы шагов для агентов

Папка нужна, чтобы агент за пару минут получил контекст шага, не читая весь `DESIGN_V9.md` (около 700 строк) и прототип
(около 4000 строк). Один шаг дорожной карты (`DESIGN_V9.md`, приложение А) это один файл в `steps/`: цель, задачи с
номерами строк, что читать, где в коде работать, миграция, тесты, приёмка.

**Как поставить задачу агенту:** "Прочитай `docs/v9/steps/NN-....md` и сделай шаг." Больше ничего пересказывать не
нужно.
Агент, с тебя: выполнение шага, переключение с мастера на созданную ветку с названием, соответствующее функционалу, шаги
для проверки, сводка выполненного.

## Правила очереди

- Шаги берутся **по порядку**. Шаг не начинается, пока предыдущий не слит и не отмечен `[x]` в приложении А. Если шаг
  застрял, можно брать следующий, не зависящий от него (колонка "Зависит от").
- Один шаг, один PR, один заход агента. Не склеивать шаги и не подтягивать задачи из соседних.

## Общие правила для всех шагов

- **Не коммитить** (`git commit` запрещён, только готовить и стейджить). Коммитит владелец.
- Отметки `[x]` в приложении А и в `FEATURES.md` ставятся, когда работа сделана и проверки зелёные, приёмку на устройстве не ждём. Если владелец просит поправить с отклонением от первоначального функционала, меняется формулировка пункта под фактическое поведение.
- Номера версий платформ (`0.9.0` на Android и iOS) не трогаются до шага 15.
- Схема БД меняется только с `.sqm` и тестом миграции на старой версии, данные не теряются.
- Все строки в `values` и `values-en`, словарь проекта (место, отряд, день, хиты, нажмите).
- Эмулятор и устройство агенты не запускают, проверку на устройстве делает владелец.
- После изменений:
  `./gradlew build -x :shared:linkReleaseFrameworkIosArm64 -x :shared:linkReleaseFrameworkIosSimulatorArm64`,
  `./gradlew ktlintFormat`, `./gradlew detekt`.

## Источники

| Файл                       | Что в нём                                                                                     |
|----------------------------|-----------------------------------------------------------------------------------------------|
| `DESIGN_V9.md`             | функциональное описание v9, приложения А-Д (дорожная карта, миграции, тесты, пакеты, приёмка) |

| `Players Codex v9.dc.html` | интерактивный прототип (вид и поведение, тексты как иллюстрация)                              |
| `v9 Design System.dc.html` | токены, иконки интерфейса, кнопки, поля, блоки, правила текста                                |
| `CORE_COMPONENTS.md`       | каталог готовых блоков: искать здесь до того, как рисовать новый                              |
| `CLAUDE.md`                | архитектура, правила кода, обязательная проверка                                              |

**Предупреждение:** номера строк в брифах привязаны к состоянию файлов на момент создания. Если строка не совпадает с
описанием, ориентируйтесь на заголовок раздела (в `DESIGN_V9.md` это `### N.N ...`, в прототипе имена состояний вроде
`xfV`, `ovVals`) и ищите через `grep -n`.
