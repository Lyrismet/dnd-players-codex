# Документация и процесс

Как в проекте появляются и описываются версии. Читает владелец и ИИ-агенты. Правила кода и архитектура в `CLAUDE.md` в
корне.

## Что где лежит

- `FEATURES.md`: что приложение умеет сейчас, по разделам (живая карта фич, `[x]` и `[ ]`)
- `RULES.md`: правила для всех версий (готовность задачи, сквозные правила продукта, имя ветки, очередь шагов)
- `CORE_COMPONENTS.md`: каталог готовых блоков интерфейса, искать в нём до того, как рисовать новый
- `vN/`, `vN-M/`: одна версия (v9.1 это `v9-1`), форма ниже. Закрытые версии только читаются
- `_template/`: пустой образец папки версии

Макеты `*.dc.html` лежат в корне репозитория и в git не попадают.

## Папка версии

- `DESIGN.md` (фаза 1, дизайн): все требования версии, задачи с пометкой **[дизайн]**, принятые решения, статус дизайна,
  открытые вопросы, пункты только для кода
- `DEV.md` (фаза 2, разработка): то же, переписанное под разработку, с миграциями, тестами и приёмкой
- `README.md` (фаза 2, для вас): список шагов, каждый с названием, целью и статусом. По нему вы выбираете, что поручить
  агенту. Агент тоже открывает его через `/step`
- `steps/NN-*.md`: бриф одного шага (цель, что читать, где работать, тесты, приёмка)

## Путь версии

```
ишью "Предложения для дизайна vN"
   |  /brainstorm #N       заводит docs/vN, переносит пункты ишью в DESIGN.md, дальше записывает решения сама
   v
фаза 1: дизайн
   |  задачи с [дизайн] вы копируете дизайн-модели (она не видит репозиторий)
   |  скриншоты и правки возвращаются в /brainstorm, решения оседают в DESIGN.md
   v
дизайн утверждён
   |  /to-dev              макет в браузере, сверка с DESIGN.md, DEV.md, карта шагов, брифы
   v
фаза 2: разработка
   |  /step или /step N    ветка, бриф, код, проверки, отметка в README и FEATURES.md
   |  устройство проверяете вы
   v
версия закрыта: пункты в FEATURES.md, папка vN остаётся историей
```

## Команды

- `/brainstorm <ишью или тема>`: обсуждение. Роль не переспрашивает, версию берёт из названия ишью, папку создаёт сама,
  решения пишет в `DESIGN.md` сразу с пометкой Принято, Предложено или Открыто.
- `/to-dev`: переход от дизайна к разработке (запускает макет и смотрит скриншоты, спрашивает про незаписанные решения).
- `/step [N]`: шаг разработки. Без номера берёт следующий свободный, создаёт ветку `s<N>_<кратко>` от свежего `master`,
  ничего не коммитит.

Версией в работе считается самая новая папка `vN` по номеру версии, указателя в `CLAUDE.md` нет.

## Что остаётся вручную

- Копирование задач дизайн-модели и возврат её результатов.
- Решение, какие расхождения макета и документа верны, если они есть.
- Выбор шага для агента (карта шагов в README версии).
- Проверка на устройстве, коммиты и слияние PR.
- Закрытие версии: перенос итогов в `FEATURES.md`.

## Принципы

- Каждое решение записывается в одном месте, без копий.
- Ссылки на документы идут по заголовку раздела, а не по номеру строки.
- Закрытая версия не правится, её требования живут дальше в `FEATURES.md`.
