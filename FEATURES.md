## 3. Упоминания @

- [x] Парсинг `@[Имя_с_подчёркиваниями|n:12]` в тексте заметки на лету: тип (`n/p/l/q`) и id записи в токене, имя
  в тексте лишь подпись. Переименование записи не трогает заметки, записи с одним именем не путаются
- [x] Дропдаун автокомплита при вводе `@` (топ-5 совпадений по имени)
- [x] Инлайн-чипы упоминаний в тексте — цвет/значок по типу и статусу сущности (● NPC, ◆ квест, ▲ локация, ■ отряд),
  зачёркивание для мёртвых NPC; "■ отряд" — упоминание персонажа отряда (`MentionEntity.PartyMention`, на карточке
  отряда есть "Связанные заметки"). (v6) Мёртвость NPC —
  отдельное поле "Состояние", а не статус отношения (см. раздел 5)
- [x] Настройка вида чипов: заливка / линия (Settings, раздел 11)
- [x] Клик по чипу — открыть карточку сущности (открывается как нижний лист, как и в самом макете)
- [x] Обратные ссылки (реализовано как «Связанные заметки», раздел 5): "Связанные заметки" на карточке сущности
  (автоматически находит все заметки, где она упомянута)

- [x] (v7) "Пустое" упоминание ("?"-тег): если упомянутую запись удалили из кодекса, в тексте остаётся тег с пунктиром
  и "?" без цвета статуса. Тап открывает боттомшит "ЗАПИСИ НЕТ В КОДЕКСЕ": "Эту запись удалили из кодекса, но на неё
  ссылаются N заметок в M сессиях"; действия — "+ Создать «X» как …" (открывает форму кодекса в боттомшите с
  подставленным именем и прежним типом, запись сама не создаётся), "Связать с другой записью" (упоминания станут
  ссылками на выбранную, с Undo), "Оставить текстом" ("?" уйдёт, имя останется словом, с Undo). Имя и тип удалённой
  записи берётся из самого токена: удалённая запись не оставляет следов, токен просто перестаёт находить запись.
  Undo удаления возвращает запись под прежним id, и "?"-теги снова становятся чипами. Персонаж отряда упоминается так же, как
  остальные: "?"-тег и "Создать как персонажа отряда" работают и для него
- [x] (v7) Предупреждение при удалении записи, на которую есть упоминания: "В заметках N упоминаний в M сессиях. После
  удаления они останутся в тексте как «?»-теги, и запись можно будет создать заново" (`CodexDeletionPlanner`,
  `CodexState.deleteWarning`); без ссылок удаление мгновенное с Undo
- [x] (v7) Авто-упоминания: после отправки или правки заметки имена из кодекса, написанные целым словом без "@",
  подчёркиваются точками, под заметкой — "N совпадения с кодексом · Связать · Нет" (счётчик золотой, без ✦; "Связать"
  делает теги разом, "Нет" снимает подчёркивания; касание слова связывает только его запись, с Undo). Правила: регистр не важен,
  "ё"="е", имя из нескольких слов ищется целиком, слово не короче 3 букв, уже отмеченные "@" пропускаются, падежи не
  находятся ("к Громму" нет). Ничего не меняется молча. Признак "ещё не решено" — колонка
  `session_entry.mention_check`, ставится при отправке и правке заметки (у старых заметок 0). Логика поиска —
  `feature/mention/domain` (`parseMentions(autoMatch = true)`, `linkAutoMentions`)
